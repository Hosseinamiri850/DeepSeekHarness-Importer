# راهنمای کاربر

راهنمای گام‌به‌گام انتقال یک گفتگوی کلاد به DeepSeek Harness (DSH).

## ۱. چه چیزی لازم است

| نیاز | چرا | بررسی |
|---|---|---|
| Node.js نسخه **۲۲.۱۵** یا بالاتر | فشرده‌سازی Zstandard داخلی | `node --version` |
| DeepSeek Harness با حداقل یک ورک‌اسپیس | ایمپورتر داخل یک ورک‌اسپیس واقعی می‌نویسد | یک بار DSH را باز کن |
| داده‌ی کلاد روی همین سیستم | منبع گفتگوها | مرحله ۳ |

به حساب، کلید API یا اینترنت نیازی نیست؛ همه‌چیز محلی اجرا می‌شود.

## ۲. اجرای داشبورد

```bash
node src/cli.js
```

یا پس از انتشار: `npx claude-to-dsh-importer`. آدرس در ترمینال چاپ و مرورگر باز می‌شود. برای پورت ثابت `--port 4173` و برای اجرای بدون بازکردن مرورگر `--no-open` را اضافه کن.

دو نشانگر وضعیت در سرصفحه می‌بینی:

- **Claude** — محل کشف گفتگوها (`~/.claude/projects`).
- **DSH** — خانه‌ی هارنس (`~/.dsh`) و وجود رجیستری ورک‌اسپیس. نقطه‌ی قرمز یعنی DSH روی این سیستم هنوز باز نشده یا `DSH_HOME` جای دیگری است.

## ۳. سشن‌های کلاد از کجا می‌آیند

### Claude Code و ایجنت محلی Claude Desktop

هر سشن یک فایل JSONL است:

```
~/.claude/projects/<پروژه-کدشده>/<session-uuid>.jsonl
```

در ویندوز: `C:\Users\<you>\.claude\projects\…`. داشبورد آن‌ها را خودکار پیدا می‌کند؛ هر ردیف پروژه، تاریخ آخرین فعالیت و تعداد نوبت‌ها را نشان می‌دهد. سشن‌های ساب‌ایجنت تا وقتی گزینه‌ی **Subagents** را روشن نکنی مخفی‌اند.

### چت‌های معمولی اپ Claude Desktop

این‌ها در IndexedDB اپ هستند و به‌صورت فایل خوانده نمی‌شوند. به‌جایش خروجی بگیر:

1. در کلاد (وب یا دسکتاپ) به **Settings → Privacy → Export data** برو.
   ([راهنمای آنتروپیک](https://support.claude.com/en/articles/9450526-export-your-claude-data))
2. ایمیل حاوی لینک دانلود می‌آید؛ آرشیو را بگیر و `conversations.json` را استخراج کن.
3. در داشبورد **Upload export** را بزن و فایل را انتخاب کن.
4. گفتگوها با برچسب `Export` در لیست ظاهر می‌شوند.

> خروجی‌ها به حساب کاربری وابسته‌اند و لینک دانلود ۲۴ ساعت اعتبار دارد. در پلن Team/Enterprise ادمین باید اجازه‌ی خروجی اعضا را فعال کرده باشد.

## ۴. مرور قبل از انتقال

با کلیک روی هر سشن دو زبانه می‌بینی:

- **گفتگو** — همان تاریخچه‌ای که منتقل می‌شود، با برچسب انسان/دستیار.
- **آمار** — نوبت‌ها، کاراکترها، تخمین توکن، فراخوانی ابزارها، حجم فایل، پروژه و زمان شروع/پایان.

در این مرحله هیچ چیزی نوشته نمی‌شود؛ پیش‌نمایش فقط خواندنی است.

## ۵. انتخاب مقصد

کنترل‌های پنل سمت چپ (در حالت RTL: سمت چپ صفحه، ستون «انتقال به DSH»):

| کنترل | معنی |
|---|---|
| **ورک‌اسپیس** | یک ورک‌اسپیس ثبت‌شده‌ی DSH. مسیر پروژه‌ی اصلی به‌عنوان `cwd` سشن استفاده می‌شود، پس سشن زیر همان ورک‌اسپیس دیده می‌شود. |
| **جای خالی موجود** | از یک ردیف سشن *خالی* که از قبل در آن ورک‌اسپیس وجود دارد استفاده می‌کند؛ بلافاصله دیده می‌شود و ری‌استارت لازم نیست. |
| **سشن جدید** | شناسه‌ی تازه می‌سازد و به `workspace.json` اضافه می‌کند؛ برای دیده‌شدن یک بار ری‌استارت DSH لازم است. |
| **سقف تاریخچه** | تعداد کاراکترهایی که از انتهای تاریخچه نگه داشته می‌شود؛ تعداد نوبت‌های حذف‌شده گزارش می‌شود. |
| **عنوان سشن** | در سایدبار DSH نمایش داده می‌شود؛ پیش‌فرض `Claude import · <پروژه>`. |

### چرا «جای خالی موجود» پیش‌فرض است

DSH پوشه‌ی سشن‌ها را اسکن نمی‌کند؛ ردیف‌های سایدبار از رجیستری ورک‌اسپیس می‌آیند. یک لاگ تازه به‌تنهایی دیده نمی‌شود. استفاده از یک جای خالی، رجیستری را دست‌نخورده نگه می‌دارد و انتقال بلافاصله پس از رفرش دیده می‌شود.

اگر ورک‌اسپیس جای خالی نداشته باشد، پنل هشدار می‌دهد. دو راه:

1. در DSH دکمه‌ی **New session** را در آن ورک‌اسپیس بزن، سپس اینجا اسکن مجدد کن.
2. حالت **سشن جدید** را انتخاب کن و بعد از انتقال، DSH را ری‌استارت کن.

## ۶. انتقال

**انتقال سشن** را بزن. کارت نتیجه تعداد نوبت‌های نگه‌داشته‌شده، تخمین توکن، شناسه‌ی سشن جدید و نیاز به ری‌استارت را نشان می‌دهد. دکمه‌ی کپی شناسه و بازکردن DSH هم همان‌جاست.

اگر جایگاه انتخاب‌شده از قبل گفتگو داشته باشد، داشبورد قبل از بازنویسی تأیید می‌گیرد و لاگ قبلی همیشه اینجا ذخیره می‌شود:

```
~/.dsh/backups/claude-import/session-<id>-<timestamp>.jsonl.zstd
```

تغییر رجیستری هم نسخه‌ی پشتیبان دارد: `workspace.json.backup-<timestamp>`.

## ۷. دیدن سشن در DSH

1. پنجره‌ی DSH را رفرش کن (`F5` یا `Ctrl+Shift+R`).
2. ورک‌اسپیس مقصد را باز کن.
3. روی سشن کلیک کن و پیام بده تا ادامه پیدا کند.

اگر حالت **سشن جدید** را انتخاب کردی، اول اپ را کامل ببند و باز کن؛ رجیستری هنگام شروع خوانده می‌شود.

## عیب‌یابی

| نشانه | علت | راه‌حل |
|---|---|---|
| `This tool needs Node.js 22.15 or newer` | نسخه‌ی قدیمی Node | Node را به‌روز کن یا با runtime همراه DSH اجرا کن |
| هیچ سشنی در لیست نیست | Claude Code روی این سیستم اجرا نشده | فایل `conversations.json` را بارگذاری کن |
| نشانگر `DSH home missing` | DSH هنوز باز نشده یا مسیر متفاوت است | یک بار DSH را باز کن یا با `DSH_HOME=<path>` اجرا کن |
| سشن در DSH نیست | حالت «سشن جدید» بدون ری‌استارت | DSH را ری‌استارت کن یا در جای خالی ایمپورت کن |
| هشدار «جای خالی موجود نیست» | همه‌ی ردیف‌ها گفتگو دارند | در DSH سشن جدید بساز و دوباره اسکن کن |
| پورت اشغال است | نمونه‌ی دیگری در حال اجراست | `--port 4174` |
| متن فارسی در لیست برعکس دیده می‌شود | برش متن با جهت مختلط | از دکمه‌ی «فا» استفاده کن؛ ردیف‌ها RTL ایزوله شده‌اند |
| خطای `409` هنگام انتقال | جایگاه از قبل گفتگو دارد | تأیید بازنویسی در دیالوگ یا انتخاب جای دیگر |

## بازگرداندن وضعیت قبلی

هر نوشتن مخرب دستی برگشت‌پذیر است:

```bash
# لاگ سشن
copy ~/.dsh/backups/claude-import/<file>.jsonl.zstd ~/.dsh/sessions/<project>/<session>/session.v4.jsonl.zstd

# رجیستری
copy ~/.dsh/storages/workspace.json.backup-<timestamp> ~/.dsh/storages/workspace.json
```

اگر رجیستری را برگرداندی، DSH را ری‌استارت کن.

## پرسش‌های متداول

**چیزی از سیستم من بیرون می‌رود؟** نه. سرور فقط روی `127.0.0.1` گوش می‌دهد و درخواست بیرونی ندارد؛ مرورگر فقط با همان پورت محلی حرف می‌زند.

**داده‌ی کلاد تغییر می‌کند؟** هرگز. `~/.claude` فقط خوانده می‌شود.

**یک سشن را دو بار می‌توانم منتقل کنم؟** بله — هر بار لاگ تازه نوشته می‌شود (یا با تأیید، جایگاه بازنویسی می‌شود).

**فراخوانی ابزارها حفظ می‌شوند؟** نه. جعل رویداد ابزار خواننده‌ی DSH را خراب می‌کند و مدل را گمراه می‌کند؛ ایمپورتر گفتگو را نگه می‌دارد نه وضعیت ابزار را.

**ادامه‌دادن سشن چقدر هزینه دارد؟** تاریخچه‌ی نگه‌داشته‌شده در هر درخواست دوباره فرستاده می‌شود؛ ۲۰۰ هزار کاراکتر تقریباً ۵۵ هزار توکن context در هر نوبت است. از انتخاب‌گر سقف تاریخچه استفاده کن.

**برگشت به کلاد ممکن است؟** با این ابزار نه؛ DSH برای لاگ‌های خودش `/export` دارد. این مسیر یک‌طرفه است.
