# انتقال سشن از Claude به DeepSeek Harness

**گفتگوهای کلاد را به سشن‌های بومی و قابل‌ادامه در [DeepSeek Harness](https://github.com/deepseek-ai) تبدیل می‌کند — از یک داشبورد محلی، بدون ارسال هیچ داده‌ای به بیرون.**

![داشبورد](assets/dashboard-fa.png)

[English](README.md) · [راهنمای کاربر](docs/USER-GUIDE.fa.md) · [User guide](docs/USER-GUIDE.md)

---

DeepSeek Harness (به‌اختصار DSH) سشن‌ها را در یک لاگ JSONL فقط‌افزودنی و فشرده‌شده با Zstandard نگه می‌دارد و هر سشن فقط وقتی در رابط دیده می‌شود که شناسه‌اش در رجیستری ورک‌اسپیس ثبت شده باشد. هیچ دکمه‌ی «ایمپورت» وجود ندارد. این ابزار همان شکاف را پر می‌کند: تاریخچه‌ی کلاد را می‌خواند، به **فرمت نسخه ۴** سشن DSH تبدیل می‌کند و در ورک‌اسپیس انتخابی نصب می‌کند تا سشن با کل تاریخچه‌اش در DSH باز شود و از همان‌جا ادامه بدهی.

## چرا وجود دارد

انتقال گفتگو بین ابزارهای هوش مصنوعی معمولاً کپی/پیست است؛ ساختار گفتگو از دست می‌رود و پنجره‌ی context پر می‌شود. این ایمپورتر ترتیب نوبت‌ها را نگه می‌دارد، قواعد اعتبارسنجی DSH را رعایت می‌کند و مهم‌تر از همه دو چیزی را حل می‌کند که باعث می‌شود یک سشن دست‌ساز دیده نشود:

1. **DSH پوشه‌ی سشن‌ها را اسکن نمی‌کند.** یک لاگ فقط وقتی در سایدبار می‌آید که شناسه‌اش در `~/.dsh/storages/workspace.json` زیر یک ورک‌اسپیس ثبت شده باشد.
2. **سشن‌ها اعتبارسنجی می‌شوند.** رویدادها باید شناسه، شماره‌ی ترتیب (seq)، «surface op» و آرایه‌ی `stream` برای پیام دستیار داشته باشند، وگرنه خواننده فایل را رد می‌کند.

## امکانات

- **دیدن همه‌ی سشن‌ها:** کشف خودکار سشن‌های محلی Claude Code / Claude Desktop از `~/.claude/projects` و همچنین فایل `conversations.json` که از *Claude → Settings → Privacy → Export data* می‌گیری.
- **پیش‌نمایش قبل از انتقال:** نمایش کامل گفتگو و آمار (نوبت‌ها، کاراکترها، تخمین توکن، فراخوانی ابزارها، پروژه، حجم).
- **کنترل حجم تاریخچه:** نگه‌داشتن N کاراکتر آخر (۵۰ هزار تا همه)، با گزارش صریح تعداد نوبت‌های حذف‌شده — چون تاریخچه در هر درخواست دوباره خوانده می‌شود.
- **دو حالت نصب:**
  - **جای خالی موجود:** از یک ردیف خالی همان ورک‌اسپیس استفاده می‌کند و بلافاصله دیده می‌شود؛ بدون ری‌استارت.
  - **سشن جدید:** شناسه‌ی تازه می‌سازد و ثبت می‌کند؛ یک بار ری‌استارت DSH لازم است.
- **پشتیبان‌گیری همیشگی:** هنگام بازنویسی، لاگ قبلی در `~/.dsh/backups/claude-import/` ذخیره می‌شود و تغییر رجیستری هم نسخه‌ی پشتیبان دارد.
- **کاملاً محلی:** سرور فقط روی `127.0.0.1` گوش می‌دهد، هیچ تماس شبکه‌ای ندارد و فقط فایل‌های همین سیستم را می‌خواند.
- **رابط دوزبانه** (انگلیسی / فارسی با چیدمان RTL) و تم روشن و تاریک.

## شروع سریع

```bash
# Node.js 22.15 یا بالاتر لازم است (Zstandard داخلی)
node --version

npx claude-to-dsh-importer        # یا: node src/cli.js
```

داشبورد روی یک پورت آزاد محلی باز می‌شود. سپس:

1. از سمت راست یک سشن انتخاب کن.
2. ورک‌اسپیس مقصد را انتخاب کن (ورک‌اسپیس‌های فعلی از رجیستری خوانده می‌شوند).
3. حالت **جای خالی موجود** را بزن و **انتقال سشن** را فشار بده.
4. DSH را باز کن، یک بار رفرش کن؛ سشن زیر همان ورک‌اسپیس است.

## چطور کار می‌کند

```
~/.claude/projects/**/*.jsonl ──► تحلیل گفتگو ──► رویدادهای v4 ──► فریم‌های zstd
conversations.json (export)  ──┘                        │
                                                        ▼
                       ~/.dsh/sessions/--<project>--/session-<uuid>/session.v4.jsonl.zstd
                                                        │
                       ~/.dsh/storages/workspace.json (فقط در حالت «سشن جدید»)
```

لاگ ساخته‌شده شامل هدر نسخه ۴، تنظیمات سطح‌سشن (مجوز/سندباکس/تأیید)، عنوان، و برای هر نوبت گفتگو یک بلوک `turn/start → step/start → user/message → assistant/message → step/end → turn/end` است. پیام دستیار فقط متن است: هیچ رویداد ابزاری جعل نمی‌شود، بنابراین تاریخچه همیشه از اعتبارسنجی خواننده‌ی DSH عبور می‌کند.

## چه چیزی منتقل می‌شود و چه چیزی نه

| منتقل می‌شود | منتقل نمی‌شود |
|---|---|
| متن انسان و دستیار، به ترتیب | فراخوانی ابزارهای کلاد و نتیجه‌ی آن‌ها |
| مسیر پروژه (سشن زیر همان ورک‌اسپیس دیده می‌شود) | تصویرها، پیوست‌ها و آرتیفکت‌ها |
| عنوان سشن و تنظیمات پیش‌فرض مجوز/سندباکس | منشأ مدل و امضای کلاد |
| مرز نوبت‌ها و زمان آخرین فعالیت | چک‌پوینت‌ها و ساب‌ایجنت‌ها (مگر با فعال‌کردن) |

نویزهای انتقال (`API Error: 4xx/5xx`، `No response requested.`، system reminder و خروجی دستورهای محلی) حذف می‌شوند تا به‌شکل یک پاسخ جعلی ثبت نشوند.

## سازگاری

- **Node.js 22.15+** — استفاده از API داخلی Zstandard (`zlib.zstdCompressSync`). بدون وابستگی بومی و بدون مرحله‌ی build.
- **فرمت سشن DSH نسخه ۴** — همان فرمتی که نسخه‌های فعلی DSH می‌نویسند.
- **ویندوز، مک و لینوکس** — مسیرها از `os.homedir()` خوانده می‌شوند و با متغیرهای محیطی قابل تغییرند.

## ایمنی

- فقط `~/.claude/**` خوانده می‌شود و نوشتن تنها داخل `DSH_HOME` است.
- هر نوشتن مخرب ابتدا پشتیبان می‌گیرد.
- اگر جایگاه انتخاب‌شده از قبل گفتگو داشته باشد، بدون تأیید صریح رد می‌شود (رابط سؤال می‌پرسد؛ API کد `409` می‌دهد).
- سرور به‌طور پیش‌فرض فقط روی loopback گوش می‌دهد.

node --test "test/**/*.test.js"    # ۷ تست: تبدیل، رفت‌وبرگشت zstd، HTTP API

## محدودیت‌ها

- تاریخچه‌ی گفتگوهای معمولی اپ Claude Desktop در IndexedDB کرومیوم ذخیره می‌شود، نه در `~/.claude`. آن را از **Settings → Privacy → Export data** بگیر و فایل `conversations.json` را در داشبورد بارگذاری کن.
- انتقال تاریخچه‌ی خیلی طولانی در اولین درخواستِ ادامه، توکن مصرف می‌کند؛ از انتخاب‌گر «سقف تاریخچه» استفاده کن.
- فراخوانی ابزارها بازپخش نمی‌شوند، بنابراین سشن منتقل‌شده نمی‌تواند یک عملیات نیمه‌تمام ابزار را ادامه بدهد.
